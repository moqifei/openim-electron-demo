# 消息转发企业成员拼音模糊搜索设计

## 背景

消息转发弹窗使用通用选择组件 `ChooseBox`。企业成员搜索目前依赖企业成员搜索接口返回结果，并对返回结果做前端过滤。当后端无法按拼音关键词检索时，接口返回空结果，前端没有候选成员可供拼音匹配，因此转发弹窗无法像顶部搜索框一样通过姓名拼音找到企业成员。

## 目标

仅增强消息转发弹窗中的企业成员搜索，使其支持姓名的中文、完整拼音、拼音首字母和部分拼音模糊搜索。

示例：

- `张三` 匹配姓名“张三”；
- `zhangsan` 匹配姓名“张三”；
- `zs` 匹配姓名“张三”；
- `zhang` 或 `san` 匹配姓名“张三”。

## 非目标

- 不改变顶部搜索框的实现；
- 不扩展群组搜索、AI/应用搜索或群内成员搜索；
- 不改变部门浏览、成员选择、已选列表和群内成员校验逻辑；
- 不改变后端接口协议。

## 设计

修改 `src/pages/common/ChooseModal/ChooseBox/index.tsx` 中企业成员搜索分支：

1. 保留当前带关键词的企业成员搜索请求，优先使用后端返回结果。
2. 将返回成员映射为选择列表后，使用现有 `filterByFuzzyPinyin` 按 `nickname || displayName || username` 进行姓名匹配。
3. 当关键词仅由字母或数字组成，且后端返回结果无法匹配时，使用空关键词请求企业成员列表，再在前端使用同一拼音过滤函数筛选。
4. 将筛选结果继续交给现有 `checkInGroup` 处理，然后更新选择列表。

这样可以复用项目已有的拼音转换和排序规则，并将行为限制在转发/选择组件的企业成员搜索路径内。

## 数据流

```text
输入姓名关键词
  -> 防抖触发企业成员搜索
  -> 后端按关键词查询
  -> 映射成员姓名
  -> filterByFuzzyPinyin
  -> 若拼音关键词无匹配：获取完整企业成员列表
  -> 本地拼音模糊过滤
  -> checkInGroup
  -> 展示可选择成员
```

## 测试策略

新增一个回归测试，覆盖“后端按拼音查询无结果，但完整企业成员列表包含目标成员”的场景，验证本地兜底过滤可以按拼音找到目标成员。测试同时验证中文姓名、完整拼音和首字母匹配由同一过滤规则处理。

实现前先运行测试并确认其因缺少目标行为而失败；实现后运行该测试及项目现有可用的构建或类型检查命令。

## 验收标准

- 在消息转发弹窗的企业成员搜索框输入姓名中文、完整拼音、拼音首字母或部分拼音，可以显示对应企业成员。
- 后端能够直接返回结果时，结果仍按现有前端拼音过滤规则处理。
- 后端无法按拼音返回结果时，前端能够从企业成员列表中完成匹配。
- 群组、AI/应用、部门浏览、成员选择及已有未提交修改不受影响。
