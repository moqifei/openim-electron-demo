# 全局截图快捷键与统一文件下载保存设计

## 背景与目标

客户端当前已有截图按钮和聊天附件下载能力，但存在两类体验问题：

1. 截图没有 `Ctrl+Shift+X` 全局快捷键，截图结果也没有稳定写入系统图片剪贴板。
2. 文件下载使用渲染进程的 `<a download>` 兜底。文件名或扩展名缺失时会退化为 `download`，Windows 保存框显示 `All Files`，且类型无法按原文件默认并允许用户修改。

本次目标是：

- 在客户端运行期间注册全局 `Ctrl+Shift+X`，窗口失焦、隐藏或最小化时仍可触发截图。
- 截图原始结果以及编辑器确认后的最终 PNG 都写入系统剪贴板，同时保留现有聊天待发送图片流程。
- 让所有普通文件下载使用统一的原生保存对话框和文件名/类型推断逻辑，覆盖聊天文件、引用消息文件、合并消息文件、多选保存文件和图片下载。
- 保持已有 TXT、ZIP 等有完整文件名时的默认行为，并修复 DOC/DOCX 等缺失文件名或扩展名时的退化行为。

截图编辑器的“保存截图”是独立的 PNG 保存动作，不纳入普通附件下载链路；它继续使用 PNG 文件名和 PNG 类型。

## 现状与约束

- Electron 主进程已有 `globalShortcut` 注册点，当前 `blur` 时会注销全部快捷键。
- `startScreenshot` IPC 已负责原生选区、原生显示器截图和 thumbnail fallback，并返回 `{ dataUrl, isSelection }`。
- 渲染进程已有截图编辑器和待发送图片队列。
- `src/utils/fileDownload.ts` 负责 XHR 下载、进度和 `<a download>` 保存；多个消息组件直接把缺失文件名转换为 `download`。
- 主进程已有 `showSaveDialog` 包装和 `fs` 写文件能力。
- 不改变消息协议、服务器接口、现有上传接口、截图分辨率修复和截图 fallback 策略。

## 设计

### 1. 全局截图快捷键

`electron/main/shortcutManage.ts` 增加 `CommandOrControl+Shift+X` 注册。快捷键注册从窗口焦点事件中解耦：主窗口创建并准备使用后注册，失焦时不再调用 `unregisterShortcuts`；退出时仍统一注销。

快捷键回调通过已有主进程到渲染进程的事件通道通知聊天页，并先唤起、聚焦主窗口。聊天页接收到事件后复用现有截图函数和用户的“截图时隐藏窗口”设置，因此快捷键不会复制截图实现，也不会改变按钮行为。

如果当前页面没有聊天页监听，快捷键不执行渲染进程截图；不会创建第二套截图窗口或改变现有权限错误处理。

### 2. 截图写入系统剪贴板

新增最小的 `writeClipboardImage` IPC：渲染进程传入 PNG data URL，主进程用 Electron `nativeImage` 创建图片并调用 `clipboard.writeImage`。

截图流程分两次写入：

1. `startScreenshot` 返回 data URL 后立即写入，使原生选区截图可以直接粘贴到外部应用，完整截图也能在编辑前粘贴。
2. 截图编辑器确认后，将裁剪或标注后的最终 PNG 再写入，确保最终剪贴板内容与用户确认的图片一致。

写入失败不阻断聊天待发送图片流程；现有截图权限错误和取消行为保持不变。

### 3. 统一文件名推断

`src/utils/fileDownload.ts` 增加纯函数式文件名推断，优先级如下：

1. 调用方提供的非空且不是占位名 `download` 的文件名；
2. HTTP `Content-Disposition` 的 `filename*` 或 `filename`；
3. 下载 URL 的最后一个路径段，去除查询参数和哈希；
4. Blob MIME 类型对应的扩展名；
5. 最终使用 `download`。

MIME 扩展名表至少覆盖 DOC、DOCX、TXT、ZIP、PNG、JPG/JPEG、PDF 和常见二进制文件。文件名推断结果保留原始扩展名大小写与主体名称，不把带扩展名的有效文件名改成另一个名称。

所有普通下载调用点取消主动传入 `download` 兜底，让统一工具能够读取响应头、URL 和 Blob 类型。图片下载也改为调用统一下载工具，沿用统一保存框和进度行为。

### 4. 原生保存对话框

新增主进程保存下载文件 IPC。渲染进程继续负责 XHR、鉴权 URL 和进度，下载完成后把二进制数据、推断文件名和 MIME 类型交给主进程。

主进程行为：

- `defaultPath` 使用用户下载目录加上 `path.basename(fileName)`，防止文件名携带路径。
- 根据文件名扩展名创建默认类型过滤器，例如 `DOCX 文件 (*.docx)`；再提供 `所有文件 (*.*)` 选项。
- 过滤器默认选中原文件类型，但用户可以在保存对话框中切换类型并编辑文件名。
- 用户取消时不写文件，调用方按正常取消处理，不显示下载失败。
- 用户确认后使用 `fs.promises.writeFile` 写入所选路径。

在没有 `window.electronAPI` 的非 Electron 环境中保留原有 `<a download>` fallback。Electron 客户端的所有普通下载统一走新增 IPC，不区分 DOC、TXT、ZIP 或图片。

### 5. IPC 边界

新增通道只承担两项职责：

- 主进程通知渲染进程触发截图；
- 渲染进程请求主进程写入剪贴板图片或弹出保存框并写入二进制文件。

截图返回结构、现有 `startScreenshot` 参数和待发送文件结构不变。保存下载 IPC 返回用户是否确认保存，避免把“用户取消”误报成网络下载失败。

## 测试设计

按 TDD 顺序实现，每项先写失败测试，再写最小实现：

- 文件名推断：有效消息文件名优先；解析 `filename*`；URL/MIME 推断扩展名；占位名最终才回退到 `download`。
- 保存过滤器：DOC/DOCX/TXT/ZIP 等扩展名生成对应默认过滤器，并包含可切换的所有文件选项。
- 下载调用：Electron 路径把 Blob 二进制交给保存 IPC；取消保存不报告下载失败；非 Electron 路径保留 anchor fallback。
- 快捷键：源码/主进程测试确认注册 `Ctrl+Shift+X`，且窗口失焦逻辑不注销全局快捷键。
- 截图剪贴板：确认截图结果和编辑器确认结果均调用写入接口，原有待发送图片仍加入队列。

## 验收标准

### 自动化验证

- 相关 Playwright 辅助测试全部通过。
- `npm run lint` 通过。
- `npm run build` 通过。
- 工作区 diff 仅包含本需求相关文件。

### 手工验证

- 客户端窗口前台、失焦、最小化/隐藏时按 `Ctrl+Shift+X`，均能进入截图流程。
- 截图原图和编辑确认后的图片都能粘贴到外部编辑器或文档。
- 下载 DOC、DOCX、TXT、ZIP、PNG、PDF 等文件时，保存框默认名称和类型与原文件一致，类型下拉可修改。
- 用户修改名称/类型后，文件按所选路径和名称写入；取消保存不会出现失败提示。

## 非目标

- 不新增独立截图窗口或重写原生截图模块。
- 不修改服务器返回字段和消息协议。
- 不改变截图权限提示、截图分辨率、编辑工具或聊天发送流程。
- 不把截图编辑器的专用 PNG 保存动作改造成普通附件下载。
